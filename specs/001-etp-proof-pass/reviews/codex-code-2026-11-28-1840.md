# Codex code review

Base: origin/dev (.)

**Verdict:** major

The reports command interpolates the user-supplied output folder into a shell command without escaping it, allowing command injection.

**Coverage:** Reviewed the spec’s Out of scope section, the supplied diff and commit log, and surrounding report scripts, tests, and ETP content. Judged against general code and security practice because the spec provides no review brief. Did not run commands or inspect files outside the snapshot.

## [major] Output folder can inject shell commands (F1)

- **Where:** scripts/report-lib.mjs:100; scripts/reports.mjs:67
- **Problem:** The output folder comes from the CLI argument, is interpolated into the Vitest command, and is then executed with `shell: true`. A folder name containing shell syntax can break out of the quoted `--outputFile` value and execute arbitrary commands with the user’s account privileges.
- **Suggestion:** Avoid a shell for this command: invoke Vitest through a process API with an argument array, or robustly quote the folder for the platform’s shell. Add a test proving shell metacharacters in a valid output folder cannot execute commands.
- **Impact:** precondition: A user runs `npm run reports -- <folder>` with a folder name containing shell syntax, such as one supplied by an untrusted script or workflow.
likelihood: Only when the command is run with a crafted folder name; ordinary folder names are unaffected. This is a security boundary because the command executes with the caller’s privileges.



## How the session handled it

- **F1, rated minor (downgraded from major), fixed.** Precondition: the person running
  `npm run reports` types a folder name containing shell syntax. Likelihood: very low; the command
  is run by hand, on the owner's own PC, by someone who can already run any shell command. Reason for
  the downgrade: no trust boundary is crossed (the only one who can pass the argument already has
  the same shell and rights), and no data is at risk. Fixed anyway: every report command now runs as
  `node <script> <args>` through `spawnSync(process.execPath, args)` with no shell, so the folder
  reaches the test runner as one argument. Test: `passes the out dir as one argument, with no shell`
  (tests/reports.test.ts), with a folder name holding `"; echo injected; "`.
